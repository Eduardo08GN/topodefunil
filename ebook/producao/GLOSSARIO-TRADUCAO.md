# GLOSSÁRIO DAS TRADUÇÕES — o ebook das 150 receitas

> Fonte da verdade das traduções **alemã** e **francesa**. ⛔ **Termo que entra
> aqui não se decide duas vezes:** se uma receita usa uma palavra desta tabela,
> usa a forma daqui.
>
> Decisões do operador: tratamento **informal** nos dois idiomas (**`du`** em
> alemão, **`tu`** em francês) e arquivos numerados **`Schritt N`** / **`Étape N`**.

## 1. ⛔⛔ MEDIDAS — o que os dois mercados realmente mudam

O texto PT **já é métrico** (g, ml, °C, kg, km) e esses números **não mudam**:
Alemanha e França usam o mesmo sistema. O que muda são as medidas **caseiras**,
e principalmente a **xícara** — que não existe em nenhuma das duas cozinhas.
Alemão e francês **pesam**.

## 4. COMO SE RODA E COMO SE MEDE

```bash
python build_tudo_tr.py todos   # gera os 18 PDFs (9 por idioma)
python build_tudo_tr.py fr      # só um idioma
python lint_traducao.py         # lente dos DADOS (16 módulos)
python medir_traducao.py        # gate do PDF (o que o comprador abre)
python snapshot_pt.py           # prova de que o PT não mudou
```

⛔⛔ **UMA ferramenta por função, NUNCA uma cópia por idioma.** `lint_de.py` +
`lint_fr.py`, ou `build_ebook_de.py` + `build_ebook_fr.py`, seriam arquivos que
divergem no primeiro conserto — e o conserto chegaria a um idioma só. Idioma
novo entra como **chave num dicionário**, nunca como arquivo novo.

⛔ **Aceite é MEDIÇÃO, nunca relato** — e as três lentes cobram coisas
diferentes de propósito:

| lente | cobra | por que existe |
|---|---|---|
| `snapshot_pt.py` | hash do HTML PT das 5 categorias | o motor virou trilíngue; o PT é produto que já vende |
| `lint_traducao.py` | paridade de forma + português solto + medida não convertida | receita perdida no meio de 700 linhas não aparece lendo |
| `medir_traducao.py` | página órfã, contagem de página, português no PDF | ⭐ **medidor de dado não mede função** — as 4 páginas de duas palavras do alemão só apareceram no PDF renderizado |

### Medido nesta entrega (2026-09-04)

- **PT byte a byte idêntico** nas 5 categorias, antes e depois do i18n, e de novo
  depois de o francês entrar.
- **16 módulos de dados: 0 ERRO**, com controle negativo (defeito plantado →
  acusado em 7 de 7 plantios).
- **18 PDFs.** Páginas contra as 360 do PT: **DE 367 (+7)** · **FR 364 (+4)** —
  ⭐ **nenhuma a menos em nenhum arquivo.** As duas línguas são mais longas que
  o português e a ordem foi *não espremer*, então elas **transbordaram para mais
  página**, com a **mesma fonte** e o mesmo CSS do PT.
- ⛔ **4 páginas órfãs achadas e zeradas** (alemão, nos sucos): o rodapé
  transbordava duas palavras (`oben anpassen.`) para uma página só dela. Conserto
  **sem encolher nada**: `break-inside/before: avoid` no rodapé, aplicado só nos
  idiomas traduzidos (`I18N[lang]["css"]`), para o PT continuar idêntico.
- **0 português vazado** no texto extraído dos 18 PDFs.
- ⚠️ **6 avisos de comprimento no francês** (`porcoes8` acima de 78 chars, por
  causa de `beurre de cacahuète`): conferidos no PDF renderizado — a célula
  **quebra em duas linhas e a linha da tabela cresce**, que é exatamente o
  comportamento pedido. Aviso é para OLHAR, não para encurtar.

## 5. O QUE NÃO SE TRADUZ

- O campo **`prompt`** de cada receita (é a instrução de foto, em inglês, e as
  fotos já existem e são **compartilhadas entre os três idiomas** — elas não
  têm texto).
- Os números: **kcal, gramas, minutos, temperaturas, faixas de peso**.
- Nomes internacionais de prato que os dois idiomas usam como estão: **Poke
  Bowl, Wrap, Curry, Couscous, Smoothie, Porridge, Crumble, Ganache**.

⚠️ **Uma exceção declarada, no molde do `DESLIGADAS` do parque:** o francês
escreve **`Séries`** exatamente como o português. O `medir_traducao.py` isenta
esse termo **só no francês** (`ISENTOS`) — cobrar isso seria a lente reprovando
copy certa, e lente que acusa o certo treina o operador a ignorá-la.
